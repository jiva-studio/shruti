# 20251011.01 - Database Refactoring

We saw warnings like “no index found” when fetching entities. Creating an index seemed correct, but on Android queries still returned no data. The fix was to avoid `$eq` for equality and use `$in` instead: `{ type: { $in: ['author'] } }`. Sorting also required a guard (it forces the index to be used): add `{ $gte: null }` for the sort field to stabilize order on Android; the previous solution `{ $exists: true }` stopped working for some reason.

## Context / symptoms

* Mango index existed and was referenced via `use_index`, but `find()` returned empty arrays on Android.
* Field `type` is **valid**; no need to mirror/rename to `docType`.
* Equality selector (`$eq`) on Android/SQLite adapter was unreliable; sorting with `sort:` also behaved inconsistently.

## Working solution (TL;DR)

1. **Selector for equality:** use a range or `$in` instead of `$eq`.

   ```js
   // Reliable equality on Android
   { selector: { type: { $in: ['author'] } } }
   // or
   { selector: { type: { $gte: 'author', $lte: 'author' } } }
   ```

   This makes indexed queries return docs as expected.

2. **`type` field is fine:** no need for `docType`. Keep the index on `type`.

   ```js
   await db.createIndex({
     index: { fields: ['type'] },
     ddoc: 'by-type-ddoc',
     name: 'by-type-index'
   });

   // Optional, but explicit
   await db.find({
     selector: { type: { $in: ['author'] } },
     use_index: ['by-type-ddoc', 'by-type-index']
   });
   ```

3. **Sorting fix on Android:** ensure the sort field participates in the selector with a non-nullable range guard.

   ```js
   // NOTE: { $gte: null } fixes sorting order on Android when `sort` is used.
   // The previous guard { $exists: true } stopped working in this environment.
   selector['sort_' + request.sort] = { $gte: null };

   const res = await db.find({
     selector,
     sort: [{ ['sort_' + request.sort]: 'asc' }],
     use_index: ['by-type-ddoc', 'by-type-index'] // if relevant
   });
   ```

## Notes / gotchas

* If indexes seem stale, re-create them: `deleteIndex` → `createIndex`.
* Keep `pouchdb` and `pouchdb-find` versions aligned and ensure the plugin is applied to the same `PouchDB` constructor you use to create `db`.
* `use_index` accepts `ddoc` **without** `_design/` or a tuple `[ddoc, name]`.

## One-liner summary

> Using `{ type: { $in: ['author'] } }` (or an equal range) made indexed queries work; the `type` field is fine. For Android sort reliability, add a guard: `selector['sort_'+request.sort] = { $gte: null }`.
